# 合规边界（对外发布红线）

> 本文件是项目的**一票否决约束**。任何代码、UI、数据如果与本文件冲突，以本文件为准。
> 状态：基于 2026-10-08 核实的现行规则。**发布前需律师复核，本文不是法律意见。**

---

## 0. 一句话定性

本项目**只做「保险条款信息的客观披露与事实并排对比」**，定性接近信息披露聚合；
**绝不做「保险销售行为」**。

分界线只有一条：**我们的页面会不会引导用户形成「买这个」的决定，以及我们是否从中获利（导流/佣金/分成）。**

- 会 → 触发《保险销售行为管理办法》，个人/无资质主体不得从事
- 不会 → 安全，但仍有宣传真实性义务（不得夸大、不得排序、不得隐瞒）

## 1. 依据的法规

| 法规 | 关键条款 | 对本项目的约束 |
|---|---|---|
| 《保险销售行为管理办法》<br>（金融监管总局令 2023 年第 2 号，**2024-03-01 施行**） | 第三条 | **除保险公司、保险中介机构、保险销售人员外，其他机构和个人不得从事保险销售行为** |
| 同上 | 第十七条 | 不得引用不真实不准确的数据；不得隐瞒限制条件；不得虚假或夸大表述；不得使用偷换概念、不当类比、隐去假设；**不得通过不当评比、不当排序等方式进行宣传**；不得冒用他人商标、字号 |
| 同上 | 第十八条 | 保险销售宣传信息须经机构事前审核授权，**销售人员未经授权不得发布保险销售宣传信息** |
| 同上 | 第二十八条 | 发现投保人需求与产品不符、支付能力不足、重复保险的，**应当建议终止投保** |
| 同上 | 第三十九条 | **任何机构、组织或个人不得违法违规开展保险退保业务推介、咨询、代办等活动** |
| 《互联网保险业务监管办法》<br>（银保监会令 2020 年第 13 号） | 第七条 | 互联网保险业务应由依法设立的保险机构开展，**其他机构和个人不得开展互联网保险业务** |
| 《中华人民共和国保险法》 | 第六条 | 保险业务由依法设立的保险公司及法律法规规定的其他保险组织经营，**其他单位和个人不得经营保险业务** |
| 《人身保险产品信息披露管理办法》<br>（银保监令 2022 年第 8 号） | 全文 | 条款、费率表、现金价值表、说明书的官方披露口径，本项目数据必须与之一致 |

原文链接：<https://www.gov.cn/gongbao/2023/issue_10826/202311/content_6915815.html>

## 2. 红线清单 —— 做了就是违规

代码层面已通过 JSON Schema 强制禁止（见 `schema/product.schema.json` 的 `additionalProperties: false`）：

| # | 禁止行为 | 说明 |
|---|---|---|
| 1 | ❌ 产品打分、排名、榜单、"优选/最佳" | 第十七条明令禁止"不当评比、不当排序" |
| 2 | ❌ "推荐购买 X" / "建议选择 X" / 任何倾向性结论 | 构成保险销售行为 |
| 3 | ❌ 投保链接、报价、核保入口的**导流或跳转** | 认定"推广 vs 销售"的关键就是有没有付款页 |
| 4 | ❌ 分享赚佣、裂变分销、返现 | 白鸽宝模式已被监管点名，见下方案例 |
| 5 | ❌ 替用户做核保判断（"你的孩子应该能过健康告知"） | 第二十八条要求建议终止投保而非促成投保 |
| 6 | ❌ 把演示利率、预期收益当作保证收益展示 | 第十七条禁止夸大与隐去假设 |
| 7 | ❌ 保险退保推荐、代办退保 | 第三十九条 |
| 8 | ❌ 隐去免责条款、折叠关键限制、超小字体 | 第十七条、第十九条 |
| 9 | ❌ 炒作停售、"即将下架"倒计时 | 第十九条，2024 年后仍是重点违规项 |
| 10 | ❌ 用"数据来源"洗白后做二次推荐 | 客观数据 + 主观结论 = 同样是销售行为 |

**案例参照**：2025 年 11 月北京商报调查的"可保快推"小程序 / 白鸽宝零门槛保险推广模式，已被律师明确指出"涉嫌违反监管对从业人员资质的要求"；其母公司白鸽在线（厦门）数字科技公开材料显示 R&D 投入占营收不足 5%，营收九成来自渠道分佣——**这正是"打着技术旗号实为分销"的红线样本**。

## 3. 绿区清单 —— 安全且这就是产品价值

| # | 允许行为 | 实现方式 |
|---|---|---|
| 1 | ✅ 条款原文并排展示 | `source.documents[].url` 直链官网/中保协 |
| 2 | ✅ 客观字段事实对比，**无排序、无权重、无默认推荐** | UI 层强制按产品名字典序排列，不提供排序控件 |
| 3 | ✅ 每字段标注来源文档 + 页码 + 原文引用 | `source.fieldTrace` |
| 4 | ✅ 数据快照日期公开 | `source.verifiedAt`，超过 90 天在 UI 上标黄警告 |
| 5 | ✅ 免责条款 / 等待期 / 免赔额 原文完整展开 | 强制字段，不得折叠 |
| 6 | ✅ 官方客服电话公示 | 《销售办法》第十四条要求保险公司公示，我们做聚合 |
| 7 | ✅ 显著免责声明 + "不构成保险建议" | 全站 footer + 首屏 |
| 8 | ✅ 教育性内容（保险知识科普） | 只讲规则和坑，不指向具体产品 |

## 4. 渠道资质矩阵

| 渠道 | 主体要求 | 类目/资质 | v1 结论 |
|---|---|---|---|
| 响应式 PWA（自建站） | 个人/企业均可 | 境内服务器需 **ICP 备案**（约 2-3 周）；不含交易不需经营性 ICP 许可证 | ✅ **可做，做 v1 主形态** |
| 微信小程序 | **企业主体** | **个人主体金融/理财/保险类目完全禁止**；企业做保险类目还需保险代理/经纪资质 | ❌ **现在物理上做不了** |
| iOS App Store | 个人开发者可发布 | 金融/保险类审核严格，通常要求资质证明 | ⚠️ **推迟**，先跑通 PWA 验证需求 |
| 本地 CLI + PDF | 无要求 | 无 | ✅ **做**，既是开发期校对工具，也可作为可下载的对比报告 |
| 数据 API | — | 对外开放接口涉及数据合规，另议 | ❌ v1 不做 |

**结论：v1 = PWA + CLI。** 另两个形态不是"排期靠后"，是**资质上现在就走不通**。

## 5. 发布前自审清单

每次部署前逐条打勾，CI 会自动跑其中可机器化的部分：

- [ ] 页面上不存在任何评分、星级、排名、"最"字开头的推荐语
- [ ] 页面上不存在任何投保/报价/核保外链
- [ ] 每个对比字段可点击展开看到来源文档、页码、原文引用
- [ ] 免责条款、等待期、免赔额、续保条件没有被折叠隐藏
- [ ] 首屏与页脚有显著免责声明，注明数据快照日期
- [ ] 数据快照日期在 UI 上可见，超过 90 天自动标黄
- [ ] 已通过律师复核（**当前未完成，见 §7**）

## 6. 命名与文案的自我约束

- ❌ 不叫「保险推荐」「保险测评」「保险榜单」「XX 排行榜」「XX 首选」
- ✅ 叫「条款对比」「信息查询」「条款事实库」「保障对照」
- 文案禁用词：`推荐` `最佳` `最优` `首选` `值得买` `闭眼入` `性价比之王` `排名` `评分` `榜`

CI 的 `lint` 会在前端文案里扫描这些词，命中即失败。
