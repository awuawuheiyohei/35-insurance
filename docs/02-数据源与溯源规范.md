# 数据源与溯源规范

> 核心原则：**每一个出现在页面上的数字，都必须能一路点回保险公司的官方文件。**

---

## 1. 数据源优先级

按可信度从高到低。**下层只能在上层缺失时使用，且必须在 UI 上标注层级。**

| 层级 | 来源 | 能拿到什么 | 可信度 | 访问方式 |
|---|---|---|---|---|
| **L1** | 保险公司官网「公开信息披露」栏目 | 条款 PDF、费率表 PDF、现金价值表 PDF、产品说明书 PDF、停售公告 | 最高 | 网页可直接访问（已验证：太保、中意等） |
| **L2** | 中国保险行业协会「中国人身保险产品信息库」<br>`https://www.iachina.cn` → 保险产品 → 人身保险产品信息库 | 条款文字编码、15 个维度产品信息、费率表、现金价值表、说明书、客服电话 | 权威交叉校验 | **Vue SPA，疑似有验证码，禁止大规模自动化抓取**；仅用于人工核对与备案号验证 |
| **L3** | 保险公司官方 App / 小程序投保页 | 实际保费、投保条件 | 高（但不可抓取） | **仅人工录入，截图存档** |
| **L4** | 第三方测评（奶爸保、深蓝保、慧择等） | 候选产品池、注意事项线索 | 低，**绝不可作为字段来源** | 仅用于"哪些产品值得看"的筛选线索 |

**红线**：任何字段的值只能来自 L1 / L2 / L3 原文。L4 出现过的数字一律不抄。

---

## 2. 溯源模型

产品的每个字段带一条 trace，指向**具体文档 + 页码 + 原文片段**：

```json
"source": {
  "verifiedAt": "2026-10-08",
  "verifier": "wang",
  "documents": [
    {
      "type": "clause",
      "title": "XX少儿重大疾病保险条款",
      "url": "https://cdn.example.com/xxx-clause.pdf",
      "sha256": "3f9a...",
      "fetchedAt": "2026-10-08"
    }
  ],
  "fieldTrace": {
    "coverage.medical.baseLimit": {
      "docIndex": 0,
      "page": 12,
      "quote": "被保险人确诊本合同所定义的重大疾病，本公司按基本保险金额的100%给付保险金。",
      "tier": 1
    }
  }
}
```

### 三条铁律

1. **`fieldTrace` 里出现过的字段名，必须和 schema 里的实际路径一一对应**，多一个少一个都算校验失败。
2. **`sha256` 是必填**。条款 PDF 会更新（`第十九条`要求变更须提前更新公示），文件变了哈希就变，能自动发现数据陈旧。
3. **`verifiedAt` 超过 90 天**，校验 CLI 降级为 warning，UI 上标黄提示"数据可能已过期"。

---

## 3. 陈旧性治理

少儿险产品迭代极快（每年 3-4 批新规，费率频繁调整），数据陈旧是这个项目**最大的风险源**——过期数据比没有数据更危险。

| 机制 | 说明 |
|---|---|
| 快照哈希 | 定期重爬 L1，sha256 变化即触发字段复核任务 |
| 停售检测 | L1 页面出现"停用日期"即把产品 `status` 置 `delisted`，前端灰显 + 顶部横幅 |
| 停售不隐藏 | 停售产品**必须保留在库中**并标注停售日期。用户会拿着停售产品去被推销，这是他们的信息优势，也是我们的价值 |
| 保鲜 SLA | `verifiedAt` 超过 **60 天**：UI 标黄；超过 **180 天**：默认折叠，需手动展开 |

---

## 4. 抓取礼仪

- 抓 L1 官网：低频（每家保险公司每周 1 次）、带 UA 标识、遵守 robots.txt、失败退避
- **不碰** L2 产品库的大规模抓取（验证码 + 属于行业基础设施，别当rawler）
- 所有抓取脚本只读，不修改任何远端数据

---

## 5. 导入流程

```
官网披露页  →  下载 PDF（L1）
              ↓
        人工阅读条款原文  →  逐字段填写 + 抄录 quote + 记页码
              ↓
        product.json（单个产品）
              ↓
        python -m insurance.validate  →  强制校验 + 哈希 + 保鲜度
              ↓
        通过才允许进入 data/products/
```

**不允许**：先填数据，来源以后补。CI 里 `fieldTrace` 缺失是硬失败。
